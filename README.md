# 条款引用重排台（Clause Reference Rearrangement Bench）

粘贴带层级编号的合同条款，拖动调整顺序后，系统自动把「第3.2条」「第5条至第7条」等引用
**先绑定到原条款，再统一重编号并改写正文**，并排展示改动前后文本；另含
**「定义术语审校」**模块，识别合同中的定义术语及其使用，报告未定义 / 重复定义 /
歧义绑定 / 未使用定义四类问题；删除条款前还可用
**「删除影响预演」**勾选拟删条款，只读预览引用失效、术语失绑及沿反向引用的
最短受影响链，确认后再一次性套用级联删除。

## 功能

### 引用重排 / 改写

- **条款解析**：识别「第1条」「第3.2条」「第3.2.1条」「第三条」「第三条之二」以及「1.2.3」式层级编号；
  正文前的「鉴于……」等说明文字原样保留。
- **层级父子树重排**：条款按编号路径构成父子树（如 `1.1.1` 的父级是 `1.1`），换序只允许发生在
  **同一父级的兄弟之间**；拖动父条款时整棵子树一起移动，删除父条款时一并删除全部后代。
  重排后各层兄弟分别从 1 连续编号（`第1条 / 第1.1条 / 第1.1.1条……`），子条款不再被
  展平成并列的顶层编号；跨父级的非法换序会被自动归正。
- **引用绑定（先绑后改）**
  - 单条引用：`第3.2条` → 绑定原路径 `(3,2)` 对应条款，重排后改写为该条款的**完整新路径**；
  - 区间引用：`第5条至第7条`、`第3-5条`、`第4.1～4.3条` → 展开为区间内全部条款；
    仅当目标**同属一个父级且新位置末段连续**时才合并为区间，否则按新顺序拆成单条或
    同级连续区间枚举；
  - 泛指引用：`本条`、`前条`、`各条` 等不报警、不重写。
- **统一层级重编号**：以原路径为身份，按拖动后的新顺序逐层编号为
  `第1条 / 第1.1条 / 第1.1.1条……`；排序页、前后对照、草稿恢复与后端返回保持同一结果。
- **最短区间生成**：重排后区间目标若被拆散，自动按新层级位置生成最短表达——
  同父且末段连续则合并为 `第x.a条至第x.b条`（两端写完整路径），否则逐个枚举，
  单条则写成其完整新路径。
- **异常检测与定位**
  - 🟠 **无法解析**：编号格式无法识别（如「第若干条」）或目标条款不存在；
  - 🔴 **目标已删除**：引用（或区间中的部分目标）指向被删除的条款；
  - 🟣 **循环引用**：条款沿引用边互相指回（如 A→B→A，包括自引用）；
  - 点击顶部问题提示或正文中的彩色标记，即可滚动定位并闪烁对应条款。
- **并排对照**：左侧改动前原文（已删除条款置灰），右侧改动后文本（引用处彩色标记）。
- **删除影响预演（预览不改草稿）**：在排序列表中勾选一项或多项**未删除条款**后
  点击「🔍 删除影响预演」，系统先只读分析、不改任何草稿状态：
  - 勾选父条款时按现有级联规则**连同后代**纳入「拟删除集」，面板区分
    ☑ 直接勾选与 ⤷ 级联后代；
  - 比较删除前后的**引用绑定**与**定义术语绑定**，列出删除后仍存活、但
    🔴 引用失效（区间只报新增失效目标）、🟠 术语失去唯一定义（变未定义）、
    🟣 变歧义绑定或 🔵 改绑其他定义的条款；
  - 存活引用图先按**强连通分量（SCC）合并**：互相指回的存活条款（含自环）
    收缩为一个循环组，**一个循环组只生成一个影响项**，组内同根因的直接影响
    去重（术语按出现处保留并标注所在成员）；
  - 在收缩后的图上沿**反向引用**给出每个受影响条款/循环组到根因的**最短原因链**
    （循环组成员、链上节点、根因与拟删除集均可点击定位），循环组以
    「↺」标注；等长链按**文档顺序**取字典序最小者；组外条款保留到根因的
    完整最短链；
  - **过期保护**：预演面板打开期间若正文、排序或删除状态发生变化，旧结果立即
    标记过期并禁用确认，需「按当前选择重新预演」；
  - 「确认删除」一次性套用现有级联删除并刷新重排、引用改写与术语审校
    （分析失败则回滚，草稿不变）；「取消」不改变草稿。
- **示例与草稿**：一键载入内置示例（含循环引用、区间拆散、无法解析等场景）；
  草稿保存在 SQLite，可随时载入/更新/删除；编辑内容同时在浏览器 localStorage 自动暂存。

### 定义术语审校（顶部「📖 定义术语审校」页签）

- **定义识别**（术语名称须在中文引号 “ ”、「」、『』 或直引号中）：
  - `“术语”是指 / 系指 / 指 …` 为**全文定义**；
  - `本合同（本协议）所称“术语”为 / 是 …` 为**全文定义**；
  - `本条（本款）所称“术语”为 / 是 …` 为**局部定义**，作用域为**所在条款及其全部后代条款**。
- **使用识别**：中文引号中的短语一律作为候选使用；已定义名称在引号外的**无引号出现**
  同样扫描；多个名称在同一位置重叠时**最长优先**（如已定义「服务」与「服务期」，
  「服务期内」绑定「服务期」而不是「服务」），并**排除定义名称本身**（定义处引号不算使用）。
- **绑定作用域**：使用处优先绑定**最近祖先条款**上的同名局部定义，找不到再回退全文定义；
  同一作用域内有多个同名定义时**不得任选**，该使用记为「歧义绑定」并列出全部候选。
- **四类问题，均在正文高亮**：
  - 🟠 **未定义**：引号短语找不到任何可见定义（若同名局部定义只存在于其他子树会提示）；
  - 🔴 **重复定义**：同一作用域内同名定义多处；
  - 🟣 **歧义绑定**：使用处命中同一作用域的多个同名定义；
  - 🔵 **未使用定义**：定义在自身作用域内没有任何确定的使用（被歧义引用指向不算使用、
    也不再另报未使用）。
- **双向定位**：点击问题条目、正文标记或左侧术语表，可在「定义 ↔ 全部使用处」之间
  滚动定位并高亮对端。
- **以当前删除状态为准**：被删除条款（含级联删除的后代）中的定义与使用一律不参与审校；
  删除条款后重新计算，剩余条款中的使用可能变为未定义。
- **忽略项**：任何问题均可「忽略」，忽略列表随草稿保存到 SQLite、载入草稿时恢复，
  也随浏览器 localStorage 暂存；正文修改导致问题消失时，对应忽略项自动清理。

### 生效版本签发（顶部「🏛 生效版本」页签）

从**已保存草稿**发起签发，把当前工作成果固化为**不可变生效版本**；草稿仍可随时
编辑，后续编辑不会覆盖任何已签发版本。

- **同一操作中固定并重跑审校**：点「🏛 签发生效版本」时，系统在同一事务中固定
  **正文、顺序、删除状态（含级联）与术语忽略项**，并重新运行引用绑定/改写与
  定义术语审校。
  - 存在 🟠 **无法解析**、🔴 **目标已删除**、🟣 **循环引用**，或任何
    **未忽略的术语问题**（未定义 / 重复定义 / 歧义绑定 / 未使用定义）时
    **拒绝签发**：侧栏列出全部阻断问题（点击可跳到对应条款），**草稿不改动、
    不产生版本**；
  - 已忽略的术语问题不阻止签发，并随版本一起固定（问题消失的失效忽略项不固化）。
- **修订号（revision）并发保护**：草稿每次保存修订号 +1，签发请求必须携带所基于的
  修订号；若校验期间草稿被其他保存改动（修订号变化），服务端返回 **409 冲突**，
  **拒绝且不产生版本**，刷新后可基于最新草稿重新签发。
- **不可变版本与摘要**：校验通过后生成该草稿内单调递增的不可变版本号（`V1、V2…`），
  记录签发时刻的条款编号（新层级路径）、每处引用的**改写结果**（原文 → 新编号）、
  **术语绑定**（定义 ↔ 使用处）与统计摘要（条款数、引用数、重写处数、术语数、
  忽略项数等）；版本内容只追加、不更新，删除草稿也保留版本。
- **重复提交幂等**：同一草稿对同一份内容（正文 / 顺序 / 删除 / 忽略项一致）重复签发，
  返回**原版本**（标记 `reused`），不会生成新版本号。
- **查看与定位**：左侧列出当前草稿的全部已签发版本；点击后右侧查看
  **生效正文（新编号）/ 签发时原文 / 术语绑定**三个视图，正文引用与术语标记均可
  点击滚动定位到对应条款；页面顶部提示版本号、签发时间与「不可变」标识。
- **操作入口**：编辑并「保存草稿」后，打开顶部 **「🏛 生效版本」** 页签，
  左侧「🏛 签发生效版本」按钮即入口；若编辑区有未保存修改，签发前会先保存当前草稿
  （修订号 +1），随后按最新修订号完成签发。

## 技术栈

- 后端：Python · FastAPI · SQLite（`uvicorn` 提供服务）
- 前端：原生 HTML / CSS / JavaScript（HTML5 拖拽，无任何前端构建步骤）

## 一条命令启动

```bash
docker compose up --build
```

启动后访问：

> **http://localhost:8000**

API 文档（FastAPI 自动生成）：<http://localhost:8000/docs>

停止：`Ctrl+C`；后台运行加 `-d`；清除草稿数据卷：`docker compose down -v`。

## 本地（不用 Docker）运行

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

访问 <http://localhost:8000> ，草稿数据库位于 `./data/drafts.db`。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/analyze` | 入参 `{text, order, deleted}`，返回解析、重编号、改写与异常结果 |
| POST | `/api/terms` | 入参 `{text, deleted}`，返回定义术语审校（定义、使用、四类问题与正文标记） |
| POST | `/api/delete-preview` | 入参 `{text, order, deleted, candidates}`，**只读**返回拟删除集（含级联）、删除前后绑定差异与最短原因链 |
| GET/POST | `/api/drafts` | 草稿列表（含修订号 `revision`、版本数） / 新建草稿 |
| GET/PUT/DELETE | `/api/drafts/{id}` | 读取 / 更新（修订号 +1）/ 删除草稿 |
| POST | `/api/drafts/{id}/versions` | **生效版本签发**：入参 `{expected_revision}`，固定正文/顺序/删除/忽略项并重跑审校；通过生成不可变版本，重复提交返回原版本（`reused:true`）；有阻断问题返回 422（结构化 `blockers`），修订号已变化返回 409，均不改草稿 |
| GET | `/api/versions?draft_id=` | 生效版本列表（可按草稿过滤），含版本号与摘要 |
| GET | `/api/versions/{id}` | 版本详情：固定的正文、条款编号、引用改写结果与术语绑定 |
| GET | `/api/health` | 健康检查 |

## 重排与改写规则速览

1. 条款以「原路径」为身份绑定引用；拖动只在同一父级的兄弟间换序，父条款移动时整棵子树
   一起移动，引用关系不丢失。
2. 重排后各层兄弟分别连续编号为 `第1条 / 第1.1条 / 第1.1.1条……`；删除父条款级联删除后代，
   剩余兄弟重新连续编号。
3. 单条引用改写为目标的完整新路径：原 `第3.2条` 随其父级变为第2条时，改写为 `第2.2条`。
4. 区间引用重写：仅当目标同父且新位置末段连续才合并。如同级目标新路径为
   `(2,1)、(2,2)、(2,3)` → `第2.1条至第2.3条`；被非同级目标隔开为
   `(2,1)、(2,3)` → `第2.1条、第2.3条`；只剩一个 → 完整单条路径。
5. 区间中部分目标已删除/不存在：剩余目标照常生成最短表达，同时给出异常提示。
6. 循环引用中的相关引用保持原文不改，标紫色并提示。

## 删除影响预演规则

1. 勾选仅来自**当前未删除条款**；父条款按既有级联规则（路径前缀）连同全部
   后代进入拟删除集，接口只做分析、不写草稿、不修改任何持久化状态。
2. 引用差异：删除前可解析且目标存活、删除后目标落入删除集的引用才算新增失效
   （区间按展开后的单条目标逐个比较，同一处引用只报一次）；删除前已失效 /
   无法解析 / 循环的引用不重复计入。
3. 术语差异：只比较删除前**唯一绑定**某定义的使用——删除后变未定义记
   「失去唯一定义」、命中多个同名定义记「变歧义」、唯一绑定的是另一存活定义
   记「改绑」；歧义改善（删除后变唯一）不报。
4. 原因链：先对删除后存活引用图求**强连通分量**并收缩为 DAG——互指条款
   （多成员 SCC）与显式自引用（自环单成员 SCC）各自作为一个循环组节点，
   **循环组只生成一个影响项**，组内同根因的引用失效去重（术语按出现处保留）；
   以含直接影响的分量为根，在收缩图上沿**反向边**多源 BFS，距离即传播跳数；
   等长链按分量首成员的文档顺序取字典序最小路径；链尾统一追加根因条款
   （被删目标 / 被移除定义所在条款，可有多个）。
5. 组外条款保留「本条款 ▸ … ▸ 根分量 ▸ 根因条款」的完整最短链；循环组的
   每个成员与全部根因均可点击定位；前置说明中的使用作为独立的「前置说明」行
   展示。
6. 预演结果与 `{正文, 顺序, 删除集, 勾选集}` 绑定；任一变化即过期，过期结果
   不能确认。确认走既有删除路径（级联删除 + 重排 + 引用改写 + 术语审校），
   取消或分析失败均不改变草稿。
